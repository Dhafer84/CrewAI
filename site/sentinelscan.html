SentinelScan

Veille passive de fuite d'information sur les dépôts publics. Le moteur est opérationnel et testé ; l'interface de scan en ligne arrive prochainement.

Principe

L'outil interroge l'API de recherche publique de GitHub — la seule plateforme grand public qui indexe le contenu des fichiers, et non seulement les noms de dépôts. À partir de termes distinctifs (nom d'entreprise, nom de projet interne, domaine e-mail), il identifie les expositions et les classe par criticité.

Échelle de criticité

NiveauSignificationDélai de traitement
CRITIQUESecret, credential, clé privée24 h
MAJEURCode ou information interne identifiable5 jours ouvrés
MINEURMention indirecte, contexte à qualifier15 jours
INFOSignal faible, veilleau fil de l'eau

Règles de conception

  • La valeur d'un secret n'est jamais lue, affichée ni stockée. Seules les métadonnées circulent : dépôt, chemin, URL, criticité. Un secret trouvé se révoque, il ne se teste jamais.
  • Sources publiques exclusivement. Le jeton d'accès est créé sans aucune permission — s'il fuite, l'impact est nul.
  • Aucun constat n'est supprimé silencieusement. Un résultat douteux est déclassé avec son motif : c'est à l'analyste de qualifier, pas à l'outil de trancher seul.

Limites assumées

Une veille dont on connaît les limites vaut mieux qu'une veille dont on croit à tort qu'elle est exhaustive. GitHub n'indexe que la branche par défaut, les Gists et Pastebin n'ont pas d'API de recherche, et un dépôt supprimé survit dans ses forks. Le rapport généré documente explicitement ce périmètre.
